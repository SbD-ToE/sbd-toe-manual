# Use cases

Most software team workflows end up falling into half a dozen patterns — someone opens a PR and needs to audit it; someone is about to write sensitive code and wants it *grounded* in a manual; someone starts a new repo and wants alignment from the outset. Rather than reinventing the use of the MCP each time, this section gathers tested recipes, each one already designed around what is typically wanted.

Every recipe has the same skeleton:

- **When to apply** — trigger signal for the agent
- **MCP call sequence** — tools, resources, prompts in the correct order
- **Output discipline** — format, IDs to cite, anti-patterns to avoid
- **Skill / subagent file** — *snippet* ready to save in the client

Choose the case that most resembles the work at hand today:

## How to read each recipe {#como-ler-cada-receita}

> 💡 The **Agentic SDLC via MCP** case is the operational view of the [end-to-end agentic process](/sbd-toe/cross-check-normativo/exemplo-playbook/exemplo-agentic-sdlc) (cross-cutting cross-check). They are coupled but separate — the regulatory view lives in the cross-check, the MCP usage view lives here.

Each page follows the same structure:

1. **Scenario** — a concrete situation in prose.
2. **Prerequisites** — *risk level* + *role* + installed skill.
3. **Flow** — sequence of MCP calls (with expected input/output).
4. **Output discipline** — format of the final report + epistemic labels.
5. **Skill / subagent snippet** — text ready to save (`.claude/skills/...`, `.github/copilot-instructions.md`, …).
6. **Anti-patterns** — what **not** to do.
